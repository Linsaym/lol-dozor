# Инструкции для разработки LoL Dozor

LoL Dozor — настольное приложение для Windows. [README](README.md) описывает окружение и запуск, а [архитектура](docs/architecture.md) — точки входа и границы React и Rust. Требования к функциям берите из текущей задачи.

## Порядок работы

1. Проверьте `git status --short` и прочитайте затронутый код. Сохраните изменения пользователя и соседних задач.
2. Установите JS-зависимости через `npm ci`, в том числе в новом worktree. Cargo берёт версию Rust из `rust-toolchain.toml`. При изменении зависимостей обновляйте соответствующий lockfile вместе с манифестом.
3. Вносите изменения в пределах задачи. Обновляйте архитектурные заметки при изменении границ системы, точек входа или команд разработки.
4. Проверяйте изменения командой `npm run check`. При изменении сборки, webview или IPC также выполните `npm run build:smoke` и проверьте запуск окна. Если доступен только браузер, проверьте фронтенд через `npm run check:web` и `npm run dev`.
5. В итоге укажите, что изменилось, какие команды прошли и какие проверки провести не удалось. Если проверка зависит от платформы, сервиса или учётных данных, назовите зависимость.

## Тесты и соглашения

- Тесты интерфейса размещайте рядом с кодом как `*.test.tsx`. Используйте Vitest и Testing Library, проверяйте наблюдаемое поведение через роли и доступные имена. Для узкого запуска используйте `npm test -- src/App.test.tsx`.
- Для поведения в Rust используйте модульные тесты рядом с кодом и интеграционные тесты в `src-tauri/tests/`. Проверяйте внешние зависимости через локальные фикстуры или подставные реализации.
- Применяйте `npm run format` и `cargo fmt --manifest-path src-tauri/Cargo.toml` по необходимости. Настройки ESLint, TypeScript, Prettier и Clippy применяются локально и в CI.
- Храните секреты на стороне Rust. Вход IPC проверяйте в Rust и добавляйте Tauri-разрешения адресно для окна и операции. Используйте обезличенные фикстуры и исключайте значения секретов из тестов, логов и UI.
